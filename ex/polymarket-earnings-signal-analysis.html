01 The Hypothesis

Polymarket is a prediction market platform where traders can gamble on real-life events. Part of the current zeitgeist amongst self-identified expert prediction traders is finding alpha: an "edge." A lot of these are non-scalable arbitrage opportunities or seem to be straight up insider trading (granted, my internet lawyers are saying it's not real insider trading).

Unfortunately, everyone and their mother are searching for arbitrage opportunities and as a result they are hard to come by and quickly filled, or met with little liquidity to take advantage of. I also can’t seem to find myself in the rooms where government military actions are being decided, so I decided to see if there were any other edges we could explore.

Hidden among the prediction markets for looming military actions and religious figures re-emerging, there exists a subset of markets that in comparison seem a little more traditional: betting YES or NO on whether publicly traded companies will beat their earnings estimates. For example, will PayPal (PYPL) beat quarterly earnings? Since Paypal reported below analyst's estimations for their quarterly earnings on February 3rd, 2026, the market resolved to NO.

At first glance, the aggregate odds don't seem useful as a signal - even in the example above, it seems at face value Polymarket traders are fairly optimistic. I wanted to put that to the test: was there any actual signal from Polymarket in which a company would beat their estimated earnings?

Once a baseline is calculated we then could explore other opportunities and see if there are any signals we could glean from a given market. For example: do late-stage swings in a market's price (say, in the final 24 hours, 6 hours, or 3 hours before an earnings report) predict how the market resolves? If traders (insiders?) with better information are moving the needle close to the deadline, that directional signal could be far more valuable than the raw odds themselves.

02 Building the Prototype

I'm an engineer by trade, so the problem decomposed naturally into a pipeline: fetch the markets, pull their full price history, and run analysis across all of them. The non-trivial part was doing it fast enough to test this idea the same morning I had it. Enter: AI.

I used ChatGPT Codex as the primary building tool, originally treating it as a co-pilot agent that could read Polymarket's API documentation and figure out implementation details I didn't want to spend time on manually (for example, undocumented behaviors like how far back the historical data actually goes).

Once Codex figured out how to effectively fetch the data, the next part was implementing an agent architecture to execute the pipeline mentioned above. After riffing a bit with Codex, I was able to easily create agents that can handle each of the steps. In the end, I constructed a multi-tiered agent architecture to fetch all of the data and test this hypothesis.

Agent 01 · Earnings Market Fetcher
Given a date range, query for resolved earnings-specific markets export findings for other agents to consume.
Agent 02 · Price History Fetcher
Consumed the output of Agent 01 and pulled full historical odds data in time-series increments for each individual market.
Agent 03 · Earnings Market History Analyzer
Consume and analyze the output of Agent 02 and return deterministic, machine-readable analytics for downstream decisioning.
Agent 04 · Orchestrator and Analyzer
Handle pipeline end-to-end: spawn and manage concurrent agents to fetch all of the required information, and finally look at and analyze the data from each specific market to highlight any trends.

Mid-run course correction: Partway through, I noticed the analyzer agent wasn't outputting results in the format the orchestrator expected — each sub-agent was quietly spinning up extra compute to reformat on its own. I stopped the run, fixed the analyzer's output contract, and re-ran with a clean instruction to sub-agents: use the tool as-is, no modifications. Catching a misaligned interface between components while the system is live was one of the more interesting parts of the morning.

Total wall-clock time was about 3 hours — a significant chunk of which was first-time setup friction with Codex. On a second run I'd scope model size more carefully by task complexity; using a frontier model with high reasoning on simple data-fetching steps was overkill and added real cost.

04 Analysis Writeup

Directional Drift - Original Hypothesis

Baseline calculation

The baseline is a naive strategy: always predict YES (the company will beat earnings). Out of the 62 markets analyzed, 41 resolved YES — giving a baseline accuracy of 41 / 62 = 66.1%. Any signal we test needs to beat this to be useful.

Analysis Windows

Let T be the market resolution time. All analysis windows end at T − 3h. So:

1h[T−4h, T−3h]
6h[T−9h, T−3h]
1d[T−27h, T−3h]
3d[T−75h, T−3h]
7d[T−171h, T−3h]
Why T - 3?: The resolution time for the prediction markets and the time when the respective companies release their earnings information usually do not line up. As a result, there’s typically a small window in which the odds converge to the “winning” bet before Polymarket resolves the market. Therefore, we exclude the last 3 hours of market data in this analysis to prevent that from biasing our analysis.

How “directional accuracy” is calculated

Pick a window, compute the YES price change based on the start and end in the window: return = price_end − price_start.

If it’s positive, that’s a YES/beat prediction; if negative, a NO/miss.

Then accuracy is correct / total, skipping windows with no movement.

Results after analyzing 62 markets

Baseline 66.1% always predict YES
1h window 58.8% worse than baseline
6h window 60.3% below baseline
1d window 67.2% roughly at baseline
3–7d window 72.4–72.6% modestly above baseline

From the data above, it seems that there is no useful correlation between sharp market pricing moves prior to the market resolving. 3 and 7 days out there seems to be a slight edge - but not anything notable compared to our easy baseline.

Bucket Analysis

Original Hypothesis

New angle: is there a correlation between a prediction market’s odds at fixed time points before resolution — specifically 1, 3, 6, 12, and 24 hours before — and the eventual outcome?

In other words, can we determine whether markets with a YES probability above some threshold N at those time points reliably resolve YES?

Parameters

For each market, take the YES probability during that hour, bucket it into 10% bands (0–10, 10–20, …, 90–100), and then compute the actual resolution rate in each bucket (how often it resolved YES vs NO).

Goal: see whether a “high” YES probability in that pre-resolution hour is actually predictive/accurate.

05 Overall Takeaways and Next Steps

The N is small (60 markets, 10 days). Before drawing any firm conclusions:

  • Expand the dataset over a longer time window to see if the 3–7 day signal and the bucket signal is real or noise
  • Define "sharp move" more rigorously — thresholding by magnitude, not just direction
  • Fine tune model usage - I used the latest frontier model for most of these steps which was costly; it could be made cheaper.

On this dataset, with this methodology, the honest answer is: probably not an edge. And knowing that quickly — in a morning, before spending a large chunk of time on it — is exactly what prototyping with AI is great for.
